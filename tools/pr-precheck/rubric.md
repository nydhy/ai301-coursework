# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's full changed-file list and every hunk, compared against the plan's Scope/Files/not-in-scope statement (including any `## Deviations` note), and the description's own claims about what changed. | Pass if every file and behavior change in the diff maps to something the plan — plus any deviation note it records — explicitly scoped in, and the description claims no more and no less fidelity than the diff actually shows. A disclosed, deliberate narrowing (a deferred case named in both the plan's deviation note and the description) is not a failure here. Fail if the diff touches a file or behavior the plan's scope excludes with no covering deviation note, or if the description's claim about what changed contradicts the diff in either direction — "implements the plan exactly" over a diff that silently touches an unscoped file, or a claimed addition ("docs now document X") that the diff does not actually contain. |  required |
| test-evidence-decisive | The Test evidence section, read against the plan's named test plan and the issue's own repro steps/artifacts. | Pass if the evidence re-runs the specific repro or scenario the plan named (not a different, unchanged, or adjacent code path) and shows a concrete before/after result tied to it, and the repo's own required checks (lint, typecheck, unit tests, integration tests, per its CONTRIBUTING docs or PR template) are reported as actually run, with their results, not merely asserted. Fail if the evidence exercises a path the fix doesn't touch, asserts an outcome ("tests pass", "verified working") with no concrete before/after shown, covers only one of several failure modes the plan's test plan named, or omits running the repo's own stated checks. | required |
| diff-reviewable | The diff's full content — every hunk — and the commit messages. | Pass if every hunk implements part of the plan's scoped change (or an explicitly deviation-noted addition), with no debug prints, commented-out code, dead or unused functions, pure reformatting/whitespace churn, or unrelated edits folded in, and commit messages describe real changes rather than only "wip"/"fix"/"fmt + cleanup". Fail if any such debris or unrelated hunk is present, regardless of whether the core fix itself is correct and well-evidenced. | required |
| standards-and-disclosure | The description, read against the repo-facts block's stated PR template sections and its AI-use/disclosure policy. | Pass if every section the repo's PR template requires is actually filled in with real content (a real `Closes #` link, a real filled checklist, a real changelog entry if the template asks for one) rather than left as the template's own placeholder text, and — where the repo's policy requires disclosing AI assistance, unconditionally or conditional on AI having been used — the description contains an explicit disclosure sentence. Fail if a required template section is visibly left blank or boilerplate, or the policy requires disclosure and the description provides none, however strong the fix itself is. | required |
| honest-shortfall | Any disclosed shortfall or deferral in the plan's deviation note and the description, read against what the diff and test evidence actually deliver. | Pass if a disclosed shortfall is stated plainly and consistently in both places, matching what was actually built. Never changes the verdict; reported for the record only — a PR that honestly discloses it did less than everything is not thereby held. | preferred |

## Verdict rule

Accept if every `required` check (`plan-fidelity`, `test-evidence-decisive`, `diff-reviewable`, `standards-and-disclosure`) grades `pass`. Any required check graded `fail` or `unclear` holds the package at `reject` — `unclear` is always treated as `fail`, since a PR this rubric cannot verify from the package is not ready to submit. `honest-shortfall` is preferred and never changes the verdict; it is reported for the record only.
